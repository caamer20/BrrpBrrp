# 0.4.0-alpha.9 — Viewer controls, operator metrics, encrypted backup custody, and the matrix gates

An alpha checkpoint, not a release. It packages the completed Phase B row set and the
first of the hardening gates from the roadmap as of 2026-10-04, and the "Known issues"
section below says plainly what has not been established.

## What this release adds

**A measured, bounded metrics surface for operators (ENG-14).** `GET /api/admin/metrics`
is a dependency-free operational surface behind operator authority: per-route request
counts, latency histograms (explicitly parameterized, never interpolated), HTTP status
classes, media forwarding and drop counters from the SFU, scheduler and queue depths, and
process RSS/CPU from `getrusage` rather than Go's heap alone. Labels are route patterns,
never request paths — a per-ID label would be a memory leak, and the negative-matrix test
suite rejects any that looks like an identifier. `scripts/probe.mjs` (`make probe`) asks a
real deployment the same questions an operator asks from outside — index, healthz, metrics,
websocket upgrade — and reports each failure as the specific fault the operator fixes next
(refused connection, upgraded-but-silent, certificate expiry), never a bare status code.

**The encrypted off-host backup procedure is written and rehearsed (ENG-15).**
`docs/deployment.md` names the tools in order (age first, then gpg, then openssl — the
trade-offs are stated, including that `openssl enc` has no authenticated mode and therefore
relies on the archive's own manifest verification), never puts the key on the server, and
spells out key custody and key loss. `make rehearsal-encrypted`
(`scripts/backup-encrypted-rehearsal.mjs`) runs exactly those steps against a disposable
installation: back up, encrypt off the host with whichever documented tool is installed
(openssl on this one), delete the plaintext, decrypt into a fresh directory, restore and
verify — 12 checks, PASS. The ledger entry records what it does not prove (off-host over a
network is Qualification, not this rehearsal).

**Three rehearsal/verification loops are now continuous (Phases B–C gates).** The negative
matrix requires every one of the **132 routes** to state how an authenticated outsider is
denied — a capability (68), the caller's own account (31), a resolved conversation (12),
channel access (10), an audience computed per delivery (6), a recipient (3), or authorship
(2) — and the classification lives in `planning/negative-matrix.json`, regenerated only by
`-update-negative-matrix` and compared byte-for-byte every run. The acceptance matrix
`planning/acceptance-matrix.json` maps every T-scenario to named, existence-checked tests
(133 named checks, 14 owed items, each owed item saying which phase owns it and what is
missing). The companion gate `scripts/check-acceptance-matrix.mjs` runs in `make check` and
CI; mutating a stale row, deleting a test, or adding a route without its row all fail the
build. Its own self-tests prove it fails when it should.

**Media: the shared-screen path is complete end to end.** The Phase B media rows landed in
the same session: viewer controls (fullscreen, view-only toggle, "controls while the video
is hidden" — the send is muted, not decoded), output-device selection (with a browser
supporting `setSinkId`, applied to every audio element including a joiner after the choice),
a measured reconnect budget (≤ 10 s to reconnect after a severed socket, ≤ 15 s to a
rejoined call carrying media again, measured `4027 ms` in a real Chromium session), and the
VP8 fallback for a viewer that cannot negotiate H.264. `docs/adr/0019-media-architecture.md`
§9–13 carry the decisions, including what an ICE restart would not rebuild.

**Reading and writing at phone width, and the tests that watch it.** A phone layout for the
viewer controls; an Arabic journey — an Arabic message, an Arabic display name, an Arabic
search — runs in the browser suite, and it found a real bug on its first run: the direction
rule was written as `direction: auto`, which is not a CSS value, so the declaration had been
dropped and every RTL message rendered LTR since that rule was added. Fixed with
`unicode-bidi: plaintext` plus `dir="auto"`; the journey asserts the resolved direction with
`getComputedStyle`, the rendered text with its line break, and the search hit. The avatar
initials' ink is now derived from the background colour with a measured-contrast band and a
clamped fallback (the deleted-member grey measured 4.0:1 — under the 4.5:1 minimum — until
an a11y sweep inside the screen-share journey caught it against a real DOM; tests cover the
product palette and a coarse sweep of the RGB cube).

**In the same tree, from the earlier tranches of this session the ledger records:**
thread authors can lock or archive their thread; the thousand-reply thread was walked to its
beginning in a real browser with every reply asserted present exactly once, the oldest
reachable, and the rendered window bounded at 200 (`thread-scale.spec.mjs`, gated behind
`BRRP_E2E_SCALE=1` because it seeds a thousand messages); Back and Forward walk the
conversation history as browser history (`pushState` on every deliberate navigation), and a
revoked conversation reached that way is re-checked against current authority rather than
shown from the entry; member profiles are reachable by keyboard from a message's author row
and from the member list, survive presence updates to the list (the bug found by the first
attempt at that assertion), and return focus to the row that opened them; a semver protocol
handshake in the `hello` frame refuses an incompatibly old client without losing drafts
(the update-required interstitial never composes over what was written); and the reconnect
policy retries on `online`/focus/resume, detects a half-open socket before reporting a
connection healthy, and is measured against the plan's ≤ 10 s p95 budget.

## Schema 25

The persistence layer is unchanged since `0.4.0-alpha.8`: schema 25, backup format 2. No
migration was added in this release, and no schema change rides in without a reason and a
qualified populated-upgrade run.

## Privacy boundary

No change to the consent, authority or privacy rules recorded in
[`docs/adr/0012-private-conversations-consent-and-shared-storage.md`](../adr/0012-private-conversations-consent-and-shared-storage.md),
[`0016`](../adr/0016-consenting-groups.md) and [`0018`](../adr/0018-delegated-moderation-and-bounded-invitations.md).
The negative matrix now has a fresh mechanical hook on every route: an all-authenticated
outsider holding valid identifiers is denied by one of the classified mechanisms on each of
the 132 routes, or the build goes red. The gates `BRRP_ENABLE_RESTRICTED_CHANNELS` and
`BRRP_ENABLE_PRIVATE_CONVERSATIONS` remain off by default, pending the owner's decision,
the independent review and the deployment qualification.

## Known issues

- **No physical-device, cross-hardware validation.** Playwright runs Chromium only; a
  Firefox project exists for the media journeys (`BRRP_E2E_FIREFOX=1 ... --project=voice-firefox`),
  and a WebKit pass does not exist. The remote media journeys haven't met a phone's
  microphone or network, a Windows machine's native lifecycle, or a Docker-covered Linux
  volume.
- **No independent security or accessibility review and no beta.** The a11y sweep is
  automated (jest-axe-derived tab and contrast rules in the journey harness); it is not a
  conformance claim.
- **No configured git remote.** One disk failure loses the whole history. Cloning from this
  environment is the only backup; nothing has been pushed anywhere.
- **The 100-account limit is stated, not yet measured,** at the reference profile (250
  account/channels/messages/clients/soak are named capacities only). The capacity tooling
  exists and speaks the deployment's transport; the runs have not been made against real
  hardware.
- **Six consecutive clean browser runs are required at candidate freeze** and are recorded
  in this tree: each loop runs to completion at negative or positive assertion failure with
  a per-run archive directory, and any run's trace is replayable (`npx playwright
  show-trace`). The record is in `planning/v1-execution-ledger-2026-10-01.md`.
- **The recovery fixtures cover the schema range written into CI** — schema 13 (a prior
  deployment's durable state, its own rehearsal) through the current — but every backup was
  taken from a still-running server. Offline database backup either copies a fixed file or
  stops the server first, so the active-writes-outrace-the-copy failure the durable case
  protects against is not exercised.

## The path from here

The candidate in the gate-for-staging sense. The remaining work is evidence on real
environments, reviews nobody in this session can credibly self-issue, and the owner's
decisions: a remote, whether to attempt the 250-account profile, whether to accept the VP8
fallback as the shipping codec policy, and when to flip the feature gates. The mechanics for
each of those is set down in the ledger; what is owed is the room to run them in.
