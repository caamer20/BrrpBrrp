# 0.4.0-alpha.5 — Community controls and dependable recovery

**Checkpoint:** 25 September 2026 (Pacific time)  
**Application:** 0.4.0-alpha.5 · **Database:** 10 · **Backup format:** 2  
**Release state:** local alpha candidate; not v1.0.0, not published, not production approved

## What members and moderators gain

- **Recovered messages:** explicit Copy/Dismiss cards for permanently refused or expired sends, without overwriting the current draft. Optional storage is account-specific, bounded and validates complete intent.
- **Message reports:** a member submits selected text and an explanation; authorized moderators review, resolve or reopen reports for channels they can currently read. Evidence availability is 90 days and disclosures describe backup retention.
- **Slow mode:** channel managers set a durable posting interval from 0 to 21,600 seconds. Acknowledged retries remain safe; deletion and restart cannot bypass the interval.
- **Voice recovery:** microphone acquisition and testing stop waiting after 30 seconds, offer an actionable retry and stop tracks that arrive after cancellation.
- **Channel notification muting:** a saved account preference suppresses live mention interruptions and queued push while preserving messages, mentions and unread counts.
- **Account removal with preserved history:** a confirmed permanent action ends the identity and keeps its conversation history under **Deleted member**, separate from reversible deactivation and explicit account/message erasure.

See the [community guide](../community-guide.md) for controls and limits, and the [account policy](../adr/0011-account-removal-and-retained-evidence.md) for retained evidence.

## Correctness and security changes

- A deleted send's old operation key remains spent. Maintenance compacts old receipts instead of deleting their replay protection; delayed original requests cannot recreate content. Legacy receipts must match the requested destination. Attachment order no longer changes otherwise identical send intent.
- Credential self-service rechecks the current session inside its committing transaction. A socket whose session has ended cannot receive a newly committed event while deferred cleanup is still pending.
- Voice permission regrant now restores forwarding without an extra client state event. The SFU keeps requested self-mute separate from access restrictions, preserving intentional self-mute, deafen and moderator controls. A real RTP regression exposed and pins this fix.
- Push registration and removal reauthorize inside their transaction. Inactive accounts cannot receive queued push. Per-channel preferences are checked again at dispatch, including between device sends.
- Removed identities cannot be reactivated or promoted. Their later socket cleanup cannot restore activity timestamps. Tombstones no longer consume live account slots; creation checks capacity in the same transaction as insertion, so simultaneous final-slot requests cannot exceed the limit. Deactivated/banned recoverable accounts still count, and tombstones do not reopen initial setup.
- Backup retention requires explicitly persisted recovery status. Unknown or malformed snapshot timestamps cannot acquire a newer recovery age from copy/completion timestamps.
- Read-cursor writes reauthorize current session and channel access in their committing transaction; an old request cannot restore personal read state after sign-out/removal. Read acknowledgements cannot move a cursor backward. Stale account/authority replies cannot restore report evidence or produce delayed muted popups.
- The full race suite now has a 20-minute per-package budget in CI and Make: its growing set of real-cost password checks exceeded Go's default ten-minute timeout on this host. Password hashing cost and test assertions are unchanged.
- A historical audit fixture is stored as `.go.txt` and copied into its proper test package by its reproduction recipe, so normal `go test ./...` no longer tries to compile it as a standalone package.

The underlying contracts are [ADR 0009](../adr/0009-authority-commit-and-admission-ordering.md), [ADR 0010](../adr/0010-conversation-model-receipts-outbox-and-cursors.md) and [ADR 0011](../adr/0011-account-removal-and-retained-evidence.md). These fixes and this implementation review do not constitute the independent security acceptance required by WP-28.

## Upgrade and rollback

Before updating, export a verified backup with the executable currently in use and retain that executable. Pending migrations apply through schema 10. Existing channel/message identifiers, rowids, attachments and search remain intact. Schemas 7–10 introduce removed identities, posting clocks, report evidence and personal notification preferences; they do not enable DMs or groups.

Rollback restores the old executable **and its matching pre-upgrade data snapshot** into a clean destination. Do not run an old binary against the migrated live database. Messages written after that snapshot are outside the rollback recovery point. Follow [updates and rollback](../deployment.md#updates-and-rollback).
