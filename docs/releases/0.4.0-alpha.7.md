# 0.4.0-alpha.7 — Threads, private calls, screen sharing, export and operator alerts

An alpha checkpoint, not a release. It is a working development tree, and the
"Known issues" section below says plainly what has not been established.

## What this release adds

**Named threads (WP-13).** A thread is a channel conversation with a subject, not a
second message store. It inherits the channel's authorization wholesale, so a thread
cannot become a way around a channel restriction, and a member's access to one changes
exactly when their access to the channel does. Start one from any message, name it, and
it is followed by default; a moderator can lock or archive it. A locked thread is still
readable and still followed; an archived one is out of the channel list but not gone.
The root message keeps its identity and its link, so anything already pointing at it
still resolves.

**Private calls (WP-20).** A call can happen in a direct conversation or a group, using
the same membership rule a private message uses, so a call ends when that membership
ends rather than on a timer. A call's participants go to its members and nobody else.
A direct pair is named for the other member, because somebody reading a participant
list needs to know who is on the line.

**Screen sharing (WP-19).** A publication is an object with a stable identity, an owner,
a kind and a lifecycle, rather than a position in a fixed list of tracks. Screen video
is carried by a forwarder on the video clock; the audio path's constants are right for
Opus and meaningless for a 90 kHz video clock, and reusing them turns a connected screen
into noise. Every way a share can fail to happen — a refusal, an insecure page, a
capture that ends on its own — is explained rather than left silent.

**A member's own data export (WP-12).** A snapshot read in one transaction, containing
only the conversations the account can read *now* and no credentials of any kind. The
bounds are applied while it is built and the file says so when it stops, because a
truncated file that looks complete is worse than a refusal. It is gated on recent
strong authentication, and a queued export does not run for an erased account.

**Moderation (WP-15).** Reports can be assigned, and the assignment is a claim about
who is expected to look rather than a grant. A timeout suspends an account without
touching its roles and restores exactly what it held, and it answers 403 with an
explanation where a ban answers 401. Invitations can admit a bounded number of people,
expire, and be revoked.

**Operator alerts.** `GET /api/admin/alerts` reports when an alert last *reached* the
destination, with the current conditions and the delivery history. A configured webhook
that has never delivered looks exactly like coverage, and the operator finds that out
during a restore.

**Composer and navigation (WP-16).** Copy link copies a permalink rather than the
message, so sharing a link never puts a private conversation into whatever it was pasted
into. An upload can be cancelled — an upload that cannot be stopped is one somebody is
trapped in — and a deliberate cancel is not reported as a failure. A failed upload is
retryable without going back to the file picker or retyping the message.

**Relay paths (WP-21).** The embedded TURN relay was UDP-only, so a client behind a
network that blocks UDP had no path at all. It now offers UDP and TCP on one ICE server
and advertises a configurable host, because a relay behind NAT that advertises its
listening address produces a call that works locally and fails for everybody else.

**TURN relay and call diagnostics.** A call reports which path it took — direct, via
STUN, or relayed. Latency cannot distinguish those, and the answer to "is it relayed?"
is needed before the answer to "how slow is it?".

## Schema 21

Schemas 14–21 are the activity, evidence, thread, moderation and export work. The
current schema is **21**; backups remain format **2** and no migration changes the
backup format. The upgrade rehearsal reports "expected 14,15,16,17,18,19,20,21 beyond
13", and the rollback rehearsal is recorded from alpha.6 at schema 12.

## Privacy boundary

- Private conversations remain **default-off** behind
  `BRRP_ENABLE_PRIVATE_CONVERSATIONS`. Nothing in this release changes that.
- A member export contains only what the account may read now. A conversation whose
  membership was withdrawn is excluded even though its messages exist.
- A call's participant list goes to the conversation's members. A channel's presence
  goes to whoever can read the channel. The two are different audiences and are
  resolved by different rules.
- Group lifecycle events are classified so that a nonmember holding only `audit.read`
  does not learn that a private group exists.
- A notification's body is built from the recipient's own preference. A failed read is
  a refusal, not a fallback to naming the sender.

## Known issues

These are the things a reader should not have to discover. None of them is a guess;
each is either unreached or unestablished.

- **The private features are default-off and have never been qualified on either
  required deployment.** Windows native/Tailscale and Linux Docker are unexercised.
  `docs/host-qualification.md` is written and has not been run.
- **No capacity or soak measurement exists.** The reference profile is 250 accounts,
  100 channels, a million messages, 100 clients, a two-hour peak and a 24-hour soak.
  The tooling exists (`make capacity-fixture`, `make capacity-load`) and the one
  recorded run is a few dozen messages on a development host over loopback. It claims
  no budget.
- **No physical microphone, no real browser capture prompt, and no call across a
  network that blocks UDP.** The browser suite substitutes a generated stream, which
  proves the forwarding path and not the media.
- **A screen share has never been seen arriving on a real client.** The negotiation,
  the bounds and the forwarding are tested, and a viewer can now ask to receive one
  without claiming a publication; nothing here shows a picture.
- **The media architecture decision is conditional on a measurement that has not been
  made.** `docs/adr/0019-media-architecture.md` chooses to extend the embedded SFU,
  and says in terms that the point at which an external SFU stops being a rewrite of
  the same logic and starts being a different deployment is the video-forwarding
  measurement at the reference allocation.
- **Right-to-left text is fixed in CSS and not verified by a rendered Arabic journey.**
- **No alert has been delivered to an operator's own receiver on a real deployment.**
  The mechanism is proven against a real HTTP receiver in tests.
- **No independent security or accessibility review, no physical-device observation,
  and no beta.** The accessibility sweep is automated and is not a conformance claim.
- **`dist/brrpbrrp` is a development build.** The alpha.7 archives under
  `dist/releases` are historical schema-14 packages and are not regenerated by this
  work.
- **There is no configured Git remote in the development environment,** so no
  canonical public repository or registry identity exists yet.
