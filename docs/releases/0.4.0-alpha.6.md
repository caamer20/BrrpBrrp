# 0.4.0-alpha.6 — Consented direct messaging

**Checkpoint:** 26 September 2026  
**Database:** 12 · **Backup format:** 2  
**Status:** local development candidate; v1 release gates remain open

## New capability

An opt-in **Messages** inbox supports direct-message requests, acceptance/rejection, withdrawal, contact preferences and blocking. Accepted members use the existing message timeline, composer, replies, files, search, pins, reactions, unread state and recovery. Administrators outside the conversation cannot browse its content. Blocking keeps accepted history read-only; unblocking does not replay failed sends. Hidden conversations remain a personal choice.

Enable `BRRP_ENABLE_PRIVATE_CONVERSATIONS=true` on a test server to exercise it. The default remains off pending the privacy/release gate. Direct calls, groups, private evidence reporting and dedicated DM push controls are not included. The server operator can read stored data; messages are not end-to-end encrypted.

## Data safety and privacy

Schemas 11–12 preserve existing channel/message identifiers, rowids, attachments, replies, pins, reactions, receipts and search while moving private messages into the shared conversation model. The upgrade handles foreign-key mode outside the rebuild transaction and retains restart recovery. Export a verified backup with the previous executable before upgrading; rollback restores that executable with its matching pre-upgrade snapshot.

Privacy regressions also fixed private-edit existence disclosure, upload capability changes during file transfer, and private pin/deletion metadata entering the community audit feed. Private link-preview requests are disabled so DM URLs are not sent to external sites. See [ADR 0012](../adr/0012-private-conversations-consent-and-shared-storage.md).
