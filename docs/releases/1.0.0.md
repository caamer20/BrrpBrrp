# 1.0.0 — stable release

**12 October 2026.** Version 1.0.0 uses the stable release channel at the owner's request.
The exact published source, qualification run, checksums and downloadable assets are recorded
in [GitHub Releases](https://github.com/caamer20/BrrpBrrp/releases/tag/v1.0.0).

Stable publication does not complete the remaining production acceptance. Clean-host and
physical-device checks, native signing/notarization, independent security/privacy/accessibility
reviews, measured capacity, soak testing and the community beta remain outstanding. See
[known limitations](../known-limitations.md) and [deployment readiness](../launch-readiness.md).

## Downloads and platforms

Native ZIPs target Windows, macOS and Linux, each on x64 and ARM64. Each archive includes the
executable, setup/service scripts, documentation, licence and dependency notices. These are
compiled distribution targets; ARM64 host acceptance and clean-host service lifecycle are
separate work. Windows/macOS binaries have no platform distribution signing identity or
macOS notarization. GitHub/Sigstore build provenance identifies the source and hosted workflow.

The source ZIP includes the Dockerfile, Compose files, build scripts and documentation for
Linux x64/ARM64 builds. No registry image is published. Members use browsers on computers,
phones and tablets; the web app is installable. Follow [installation](../installation.md),
[Docker](../docker.md) and the [user manual](../manual/README.md).

## Changes from 1.0.0-rc.1

- Align the application, frontend/lockfile and archive builder on version 1.0.0.
- Draft versions without a prerelease suffix use stable metadata. Suffixed versions retain
  prerelease metadata. Every draft stays non-latest until verified and deliberately published.
- Update current guides to separate stable publication from production deployment sign-off.
- Retain `main` and the badge-only `badges` snapshot branch. The live README download count
  uses Shields and needs no scheduled Actions job.

This release introduces no application behavior or data migration changes from the qualified
RC. That release's toolchain, security and browser harness repairs remain included: Go 1.27.2,
x/net v0.60.0, parameterized activity filters, explicit integer/ZIP guards, complete-source
CodeQL review, three Chromium modes, WebKit core and Firefox synthetic media transport.

## Compatibility and upgrade

**Application 1.0.0 · database schema 25 · backup format 2 · WebSocket protocol 1.**
There is no new schema migration from alpha.9 or 1.0.0-rc.1. Read [upgrading](../upgrading.md)
and [compatibility](../compatibility.md), keep a verified pre-upgrade backup and matching prior
executable, and use offline restore for rollback. Host configuration and TLS material need
their own private backup.

Restricted channels and private conversations remain enabled when their configuration switches
are unset. Set `BRRP_ENABLE_RESTRICTED_CHANNELS=false` and
`BRRP_ENABLE_PRIVATE_CONVERSATIONS=false` before upgrading to keep them disabled. Neither
feature has received independent security/privacy review. Existing explicit settings are preserved.
New installations schedule backups every 12 hours, retaining seven copies; configure and
rehearse an off-host destination. Existing backup settings are preserved.

## Verification and remaining work

Publication requires a new exact-source run of all automated qualification families, followed
by checks of the actual downloadable ZIPs, inventories, binary identities, checksum manifests,
SBOM and signed provenance. The [GitHub release](https://github.com/caamer20/BrrpBrrp/releases/tag/v1.0.0)
records that run and its actual results. Prior RC results do not qualify newly built 1.0.0 bytes.

The qualification workflow covers native Go suites on three operating systems, dependency and
secret audits, whole-source CodeQL/findings review, five race shards, browser engines/modes,
Docker lifecycle/builds, recovery, historical migration/rollback, and extracted package consumers.
A full-disk rehearsal can skip when the hosted runner cannot mount its disposable image; the
published notes must disclose its actual outcome. A skip does not exercise that scenario.

Automated media uses synthetic loopback tracks. Real microphones, displays, external networks,
UDP-blocked calls, physical mobile push/PWA behavior and off-host restoration remain unqualified.
Broader restricted role/announcement/voice acceptance, fault-injected messaging, repeated sharing,
two-device state, capacity and beta work remain in the [roadmap](../../ROADMAP.md) and
[production runbook](../production-readiness.md). Implementation limits are not measured capacity.

Report ordinary bugs through GitHub issues. Use GitHub's private vulnerability reporting for
security reports, as described in [SECURITY.md](../../SECURITY.md).
